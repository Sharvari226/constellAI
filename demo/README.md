# ConstellAI demo dashboard

All files in this directory are demo-only. The demo imports the existing `constellai` package and calls its TLE parser, SGP4 propagator, altitude-band calculation, coarse candidate filter, and canonical graph builder. It does not modify research modules.

## Requirements

- Python 3.11+
- Install the repository from its root (`pip install -e ".[dev]"`).
- Install demo UI dependencies (`pip install -r demo/requirements.txt`).

## Windows PowerShell: run everything

From the repository root:

```powershell
# 1. Environment (skip if already active)
python -m venv .venv
.venv\Scripts\Activate.ps1

# 2. Install existing project + demo dependencies
python -m pip install --upgrade pip
pip install -e ".[dev]"
pip install -r demo/requirements.txt

# 3. Fetch ~50 current Starlink TLEs, propagate with existing M1 code,
#    and run the existing M2 coarse + fine screening pipeline
python demo/scripts/prepare_starlink_snapshot.py --count 50 --hours 2 --step-minutes 2

# 4. Launch dashboard
python -m streamlit run demo/dashboard/app.py
```

Open the local URL printed by Streamlit (normally http://localhost:8501).

## Linux / macOS

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -e ".[dev]"
pip install -r demo/requirements.txt
python demo/scripts/prepare_starlink_snapshot.py --count 50 --hours 2 --step-minutes 2
python -m streamlit run demo/dashboard/app.py
```

## Reuse the saved snapshot offline

```bash
python demo/scripts/prepare_starlink_snapshot.py --offline --count 50 --hours 2 --step-minutes 2
```

## Optional M2 screening settings

```bash
python demo/scripts/prepare_starlink_snapshot.py --count 50 --hours 2 --step-minutes 2 --margin-km 50 --distance-km 300 --min-closing-rate 0
```

The first stage is `candidate_pairs_by_regime`; the fine stage is the repository's `build_graph`, which calls `screen_candidate_pair` and the existing `screen_pair` implementation. The saved `data/processed` CSV/JSON files are generated by the demo.

## Tests

```powershell
python -m pytest demo/tests -q
```

## Output files

- `data/raw/starlink_snapshot.tle`: downloaded TLE snapshot.
- `data/processed/satellites.csv`: SGP4 state and orbital elements at a common epoch (TEME frame).
- `data/processed/candidate_pairs.csv`: coarse M2 candidates.
- `data/processed/screened_edges.csv`: fine-screened conjunction edges.
- `data/processed/snapshot_metadata.json`: source, epoch, parameters and counts.

## Evidence boundaries

The Starlink data path is a real-data snapshot demonstration for M1/M2. It is not a live continuously updating feed and does not imply that the synthetic Stream-7 risk/maneuver metrics were evaluated on Starlink. The dashboard reads `artifacts/04_final_results/final_stream7_report.csv` from the repository for the frozen trigger-ladder comparison. M3/M4/M5 are not presented as having saved final evaluation outputs where the repository's visualization README says those outputs are absent. No formal safety guarantee or operational maneuver recommendation is made.
